01
Getting Started
R Introduction & Operators
🇷
What is R

Built for Statistics

R is a free, open-source language and environment created specifically for statistical computing and graphics. Unlike general-purpose languages that treat statistics as an afterthought, R was designed from day one around vectors, data frames, and built-in statistical/plotting functions — which is why it feels unusually natural for data analysis once the syntax clicks.

⌨️
Assignment & Basics

Variables, Types, Comments

  • <- is the idiomatic assignment operator (= also works)
  • Basic types: numeric, integer, character, logical, complex
  • # starts a comment — R has no multi-line comment syntax
  • class() and typeof() reveal a variable's type
🧮
Arithmetic Operators

+ − * / ^ %% %/%

Standard arithmetic (+ - * /) plus exponentiation ^, modulus %% (remainder), and integer division %/%. All of these are vectorised — applying an operator to two vectors works element-by-element automatically, no explicit loop required.

⚖️
Relational & Logical

Comparisons & Boolean Logic

  • Relational: == != > < >= <= → return TRUE/FALSE
  • Element-wise logical: & (AND), | (OR), ! (NOT)
  • Short-circuit logical (single result): &&, || — used in if() conditions
  • Special operator %in% tests membership in a vector
# assignment, vectorised arithmetic, and comparisons
x <- 10
y <- 3
x %% y        # remainder
#> [1] 1
x %/% y       # integer division
#> [1] 3

v <- c(2, 4, 6)
v * 10          # vectorised — no loop needed
#> [1] 20 40 60

5 %in% v      # membership test
#> [1] FALSE
Why R Feels Different at FirstComing from a language like Python or Java, the biggest mental shift is that almost everything in R is a vector — even a single number like 10 is technically a vector of length one. Once that clicks, operations that look like "magic" (applying *10 to a whole column of data at once) stop feeling magical and start feeling obvious.
😂 Lab HumorR's assignment arrow <- is basically the language's way of saying "I refuse to let you forget which direction data is flowing." Meanwhile = also works for assignment, just to keep everyone humble and occasionally confused during code review.

02
Data Structures
Vector, List, Matrix, Data Frame & Factor
📏
Vector

The Atomic Building Block

A vector is an ordered, 1-D collection where every element must be the same type (all numeric, all character, etc.), created with c(). Nearly every other R structure — matrix, data frame column, factor — is built on top of the humble vector.

🧺
List

The Flexible Container

A list is also ordered and 1-D, but each element can be a different type or even a different structure entirely — a list can hold a number, a character vector, a data frame, and another list all at once. Access with [[ ]] (single element) vs [ ] (sub-list).

🔲
Matrix

2-D, Single Type

A matrix is a vector reshaped into rows and columns via matrix() — still restricted to one data type. Useful for linear algebra (%*% matrix multiplication, t() transpose, solve() inverse) and any strictly numeric grid of data.

📋
Data Frame

2-D, Mixed Types by Column

A data frame is R's workhorse for real datasets — rectangular like a matrix, but each column can hold a different type (numeric age, character name, logical flag), while every value within a column still shares one type. Created with data.frame(); almost every dataset you import lands here.

🏷️
Factor

Categorical Data

A factor stores categorical variables (e.g. "Low"/"Medium"/"High") as integer codes plus a set of labelled levels — memory-efficient and lets R know the variable is categorical (or even ordered) rather than free text, which matters for modelling functions like lm().

⚠️
Choosing the Right One

Quick Decision Guide

  • One type, 1-D → vector
  • Mixed types, 1-D → list
  • One type, 2-D → matrix
  • Mixed types, 2-D (rectangular data) → data frame
  • Fixed set of categories → factor
# vector — all one type
scores <- c(88, 92, 79)

# list — mixed types, mixed structures
student <- list(name = "Meera", age = 23, scores = scores)
student$scores
#> [1] 88 92 79

# matrix — reshaped vector, 2 rows x 3 cols
m <- matrix(1:6, nrow = 2)
t(m)                 # transpose

# data frame — mixed types by column
df <- data.frame(name = c("Meera", "Rafi"),
                  score = c(88, 95),
                  pass  = c(TRUE, TRUE))
str(df)

# factor — categorical levels
grade <- factor(c("B", "A", "C"), levels = c("C","B","A"), ordered = TRUE)
grade
#> [1] B A C
#> Levels: C < B < A
R's Core Data Structures at a Glance
Plain-English RecapA vector is a single-flavour box of items in a row. A list is a mixed bag — anything goes, in any order. A matrix is that same single-flavour box, folded into a grid. A data frame is a spreadsheet — each column has its own flavour, but every cell in that column matches. A factor is a spreadsheet column that's secretly just numbers wearing category name-tags.
😂 Lab HumorA vector is like a carton of eggs — twelve of the exact same thing. A list is like your backpack — a laptop, a sandwich, and somehow three pens that don't work. A data frame is what happens when you finally organise your backpack into labelled compartments and insist everyone follow the labelling rules.

03
Control Flow
If…Else, switch(), while, for & repeat
🔀
if / else if / else

Branching on a Condition

Executes a block only if a single logical condition (TRUE/FALSE) holds; else if chains additional conditions, and a final else catches everything else. Note: the condition must resolve to exactly one TRUE/FALSE, not a vector (use ifelse() for vectorised branching).

🎛️
switch()

Multi-Way Branching

A cleaner alternative to a long if/else if chain when branching on the exact value of a single character or integer expression — matches a case and returns/executes the corresponding value, falling through to a default if none match.

🔁
for Loop

Iterate Over a Known Sequence

Repeats a block once for each element of a vector or list — the go-to loop when you know in advance what you're iterating over (rows of data, elements of a vector, files in a folder).

⏳
while & repeat

Iterate Until a Condition Changes

  • while(cond): checks the condition before each iteration — may run zero times
  • repeat { ... break }: runs the body first and relies on an internal break to stop — guarantees at least one iteration
  • next skips to the following iteration in any loop type
if (score >= 90) {
  grade <- "A"
} else if (score >= 80) {
  grade <- "B"
} else {
  grade <- "C"
}

switch(day,
  "Sat" = ,
  "Sun" = "Weekend",
  "Weekday")

for (i in 1:5) {
  print(i^2)
}

n <- 1
while (n <= 3) { print(n); n <- n + 1 }

repeat {
  print("runs once, then checks")
  break
}
for vs while vs repeat — When Each One Checks Its Condition
Plain-English RecapUse for when you already know exactly what you're looping over. Use while when you don't know how many iterations you'll need, but you can check "should I keep going?" before starting. Use repeat for the rarer case where the body absolutely must run at least once before that check makes sense (e.g. "ask for input, then validate it").
😂 Lab Humorfor is the disciplined student who knows exactly how many chapters are left to read. while is the person who keeps studying "until I feel ready," which could be ten minutes or ten hours. repeat is the person who starts the exam first and only afterwards asks, "wait, was I supposed to stop at some point?"

04
Functions
R Functions & the Apply Family
🧩
Defining Functions

function(args) { body }

Functions are created with function() and assigned to a name like any other object — R treats functions as first-class values, so they can be passed as arguments to other functions. The last evaluated expression is returned automatically, or use explicit return().

🎚️
Arguments & Defaults

Flexible Calling

  • Default values: function(x, digits = 2)
  • Arguments matched by position or by name
  • ... ("dots") captures any extra, unnamed arguments — used heavily to pass options through to inner functions
🔂
Why the Apply Family Exists

Vectorised Iteration Without Explicit Loops

R functions like sapply()/lapply() replace many for loops with a single, often faster and more readable call: "apply this function to every element/row/column," letting R handle the iteration internally.

🗂️
The Main Players

sapply, lapply, mapply, apply

  • lapply(x, f): applies f to each element of x, always returns a list
  • sapply(x, f): like lapply, but simplifies the result to a vector/matrix when possible
  • apply(m, MARGIN, f): applies f over rows (MARGIN=1) or columns (MARGIN=2) of a matrix/data frame
  • mapply(f, x, y): applies f over multiple vectors in parallel, element-wise
# defining a function with a default argument
bmi <- function(weight_kg, height_m, digits = 1) {
  round(weight_kg / height_m^2, digits)
}
bmi(70, 1.75)
#> [1] 22.9

# apply family — no explicit for-loop needed
nums <- list(1:3, 4:6, 7:9)
sapply(nums, sum)
#> [1]  6 15 24

m <- matrix(1:6, nrow = 2)
apply(m, 1, sum)   # row sums
#> [1]  9 12
apply(m, 2, sum)   # column sums
#> [1]  3  7 11
Plain-English RecapThink of the apply family as saying "here's a job (a function), here's a stack of things to do it to (a list, vector, or matrix margin) — go." R loops internally, often faster than a hand-written for loop, and the code reads almost like a sentence describing the intent rather than the mechanics.
😂 Lab Humorfor loops are you personally walking to every desk in the office handing out the same memo. sapply() is hiring an intern to do it for you and just come back with a neatly organised report. Same job, wildly different amount of your own typing.

Import & Export Data
Reading & Writing CSV & Excel Files
📄
CSV Files

Base R, No Packages Needed

read.csv() reads a comma-separated file straight into a data frame; write.csv() writes one back out. Both are base-R functions — no installation required — which makes CSV the most portable, dependency-free format for sharing tabular data.

📊
Excel Files

Needs a Package

Base R can't read .xlsx natively. The readxl package's read_excel() reads Excel files (including choosing a specific sheet), and the writexl or openxlsx packages write data frames back out to .xlsx.

⚙️
Useful Arguments

Getting the Import Right

  • header = TRUE — first row holds column names (default for CSV)
  • stringsAsFactors = FALSE — keeps text as character, not factor (R's modern default)
  • sep = ";" — for semicolon- or tab-delimited files
  • sheet = "Sheet2" or sheet = 2 — which Excel sheet to read
⚠️
Common Pitfalls

Watch Out For

  • Wrong working directory → "file not found" (check with getwd())
  • Locale-dependent decimal commas in European CSVs (read.csv2() handles these)
  • Row names accidentally imported as a data column
# CSV — base R, no package needed
df <- read.csv("students.csv", header = TRUE, stringsAsFactors = FALSE)
write.csv(df, "students_out.csv", row.names = FALSE)

# Excel — needs a package
library(readxl)
df <- read_excel("students.xlsx", sheet = "Sheet1")

library(writexl)
write_xlsx(df, "students_out.xlsx")
Plain-English RecapCSV is the plain-text, universally readable format — like a note written on a plain index card that anyone can read. Excel files are richer (multiple sheets, formatting, formulas) but that richness is exactly why R needs an extra package (readxl/writexl) to unpack them properly.
😂 Lab Humorread.csv() is the friend who shows up to a potluck with exactly what the invite said: rice, in a bowl. read_excel() is the friend who shows up with a seven-tier casserole dish, three garnishes, and a note about which layer is gluten-free — delicious, but you're definitely going to need the right utensils (packages) to serve it.

06
R Base Graphics
plot(), bar, scatter, box, histogram, pie & QQ
📈
plot()

The Universal Starting Point

plot(x, y) is base R's do-everything function — its behaviour adapts to the class of its input (numeric → scatter, factor → boxplot, a fitted model → diagnostic plots), making it the natural first stop for a quick look at data.

📊
barplot() & pie()

Categorical Summaries

barplot(heights) draws bars from a numeric vector (often a table of counts); pie(values) draws proportional slices from the same kind of summary. Bars are almost always preferred by statisticians for comparing magnitudes — pies make precise comparison harder for the human eye.

🔵
Scatter & Box-Whisker

Relationships & Spread

  • plot(x, y) with two numeric vectors → scatter plot, for relationships between two variables
  • boxplot(x) or boxplot(y ~ group) → shows median, quartiles, and outliers per group at a glance
📶
hist() & qqnorm()

Distribution Shape

  • hist(x) — bins a numeric vector to visualise its distribution's shape, skew, and modality
  • qqnorm(x) + qqline(x) — plots sample quantiles against theoretical normal quantiles; points hugging the line suggest approximate normality, key for checking assumptions before t-tests/ANOVA
x <- c(2,4,6,8,10); y <- c(3,7,6,9,12)

plot(x, y, main = "Scatter", pch = 19, col = "steelblue")
barplot(table(c("A","B","A","C","A")), col = "tomato")
boxplot(y ~ rep(c("grp1","grp2"), c(3,2)))
hist(rnorm(200), breaks = 20, col = "lightgreen")
pie(c(30,45,25), labels = c("A","B","C"))
qqnorm(rnorm(100)); qqline(rnorm(100), col = "red")
Plain-English RecapBase graphics are R's "sketch it on a napkin" tools — fast, dependency-free, and perfectly fine for exploratory checks while you're actually doing the analysis. They trade some visual polish for speed and simplicity; that's exactly the gap ggplot2 fills below when a chart needs to leave the napkin and go into a report.
😂 Lab HumorA pie chart is what happens when a bar chart decides it wants to be dramatic and round instead of useful and comparable. Statisticians tolerate pie charts the way chefs tolerate pineapple on pizza — technically allowed, rarely the professional's first choice.

ggplot2 Graphics
The Grammar of Graphics — Bar, Scatter & Box-Whisker
🧱
The Core Idea

Layered, Not Monolithic

ggplot2 (part of the tidyverse) builds a plot as layers added with +: start with ggplot(data, aes(x, y)) to map data to visual properties, then add a geometry layer (geom_bar(), geom_point(), geom_boxplot()) that decides how those mappings are drawn.

📊
geom_bar() / geom_col()

Bar Plots

geom_bar() counts rows per category automatically; geom_col() plots pre-summarised values directly (you supply the bar heights). Add fill = group inside aes() to colour bars by a second categorical variable.

🔵
geom_point()

Scatter Plots

Maps two numeric variables to x/y position as points; layering geom_smooth(method="lm") on top overlays a fitted trend line with a confidence band in a single extra line of code — a very common exploratory move.

📦
geom_boxplot()

Box-Whisker Plots

geom_boxplot(aes(x=group, y=value)) draws one box per group automatically, with outliers plotted as individual points — the ggplot2 equivalent of base R's boxplot(y ~ group), but themeable and combinable with other layers.

library(ggplot2)

# bar plot
ggplot(df, aes(x = category, fill = category)) +
  geom_bar() +
  theme_minimal()

# scatter plot with a fitted trend line
ggplot(df, aes(x = height, y = weight)) +
  geom_point(colour = "steelblue", size = 2) +
  geom_smooth(method = "lm", se = TRUE)

# box-whisker plot by group
ggplot(df, aes(x = group, y = score, fill = group)) +
  geom_boxplot() +
  labs(title = "Score by Group", x = NULL, y = "Score")
ggplot2's Layered Grammar — Building a Plot Piece by Piece
Plain-English RecapBase R graphics are a single command that draws one finished picture. ggplot2 instead treats a chart like a layered cake: data and mappings first, then a geometry decides the shape, then labels/themes/facets are stacked on top with + — which is why customising or extending a ggplot2 chart (add another layer, facet by a variable) is usually a one-line change rather than a rewrite.
😂 Lab HumorBase R plotting is ordering "the usual" at a diner — fast, no menu needed, done in ten seconds. ggplot2 is building a burger at one of those build-your-own places: bun layer, patty layer, toppings layer, sauce layer — slower to order the first time, but exactly the burger you actually wanted.
